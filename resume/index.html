AI-Native Engineering

AI 가 자동으로 할 수 있는 일은 환경을 만들어 맡기고, 그렇게 생긴 시간을 사람의 검토와 정제에 씁니다.

자동화 → 시간 확보 → 사람의 검토·판단 → 기준화 → AI 하네스 → 더 정교한 자동화 → 반복
  • ◆ 작업이 끝나면 문서가 남는 구조: 티켓 분석 → 구현 → 리뷰 → PR → 문서 갱신을 Claude Code 스킬로 한 흐름으로. 문서화 시간을 따로 잡지 않아도 도메인 문서·트러블슈팅·ADR 이 같이 갱신됩니다 (ADR 279건 · 지식 문서 1,144건 · 1,060페이지 상시 발행)
  • ◆ 사람이 검토하는 단계: 메인 세션은 설계·검토, 구현은 서브에이전트에 위임하고 결과 diff 를 직접 읽습니다. 근거(코드 경로·commit SHA) 없는 문장은 TODO-VERIFY 로 표시, 문서·코드 괴리는 린트로 탐지, 운영 판단은 DB 와 로그로 확인한 뒤에만 결론
  • ◆ 팀 정책 저장소 + 플러그인: 코드를 열지 않아도 도메인 규칙에 답하는 저장소에 규칙 432건을 ID 로 이관. 세션 시작 hook 이 변경 파일 경로로 도메인을 추론해 규칙을 먼저 읽게 함. 팀원 5명 PR 12건, 정책 판정 누락 PR 은 4개 레포 CI 가 머지 차단
